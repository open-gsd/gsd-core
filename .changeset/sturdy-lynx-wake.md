**`state milestone-switch` keeps custom STATE.md frontmatter keys, and neither it nor `milestone complete` silently deletes operator lines from `## Current Position`** — milestone-switch rebuilt the frontmatter from a fixed key list, so a custom key such as `team_owner` was lost; both commands replaced the whole Current Position body with the four template lines, so lines like `Blocked on:` or `Carry-over:` vanished without a trace. Unknown frontmatter keys now survive the switch unchanged, with their full-line and inline comments (the switch splices the frontmatter and regenerates only the keys it resets), and a frontmatter mapping nested four or more levels deep is written in full instead of as `[object Object]`. Every Current Position line other than the fields the state commands own (the first `Phase`, `Plan`, `Status`, `Last activity`, `Progress`, `Current Plan`, `Total Phases` and the other fields the frontmatter sync reads) is moved, once and in order, under `## Accumulated Context` (created when absent) and listed in the JSON result as `moved_current_position_lines` (absent when nothing moved, as for a STATE.md made from the shipped template). A moved line the frontmatter sync would still read as one of those fields, such as a second `Status:` line, is written as a list item (`- Status: ...`) so an old-milestone value cannot return to the frontmatter; a fenced block left unclosed is closed. The reset of the template fields is unchanged. (#6174)
