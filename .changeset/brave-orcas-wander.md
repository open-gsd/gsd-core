**On Claude Code, Agent() calls are checked against the model GSD resolved** — an orchestrator that passed `gsd-executor`, `gsd-verifier`, `gsd-plan-checker` or `gsd-planner` a model other than the resolved one ran that agent on the wrong tier without a word; the isolation hook now warns (or, with `hooks.agent_model_guard: "deny"`, blocks a wrong or an omitted model) and accepts a model `resolve-execution --attempt N` recorded within the last 10 minutes; with `--ws`, `init` records the workstream name for the session (the newest eight, each for 12 hours) so a model matching any recorded workstream's baseline or the `GSD_WORKSTREAM`/pointer one passes; both commands now write outside the planning files: `resolve-execution` with `--attempt N` or `--failure-class` creates `.gsd/model-escalation-<agent>.json` in the project, git-ignored through `.gsd/.gitignore`, when it resolves a model of another tier family than the baseline, and `init --ws` writes a carry file under the OS temp directory, only where the guard applies, a session id exists and the workstream directory exists, and each `init` where the guard applies prunes carry files after 7 days; a `--project-dir` or `--cwd` that names another root than the session's records no escalation, and `resolve-execution` then prints `gsd: model-escalation record not written` on stderr where the guard applies, as `init --ws` prints `not recorded for the Agent model guard` where the guard applies and it has no session id.
