**`config-new-project` now refuses the choices `config-set` refuses** — an unknown key, or a value outside a key's allowed set (such as a `mode` placeholder left unfilled), now fails with the same error `config-set` gives, and no config is created. A dotted key in place of a nested one, and choices that are not a JSON object, are refused as well. An empty object under a name that is not a section is refused as an unknown key, and a section given anything but an object is refused. Values are JSON-typed and not coerced, so `"true"` where a setting takes a boolean is refused. Before, all of these were written into the new project's `.planning/config.json` and the command reported success. A `null` choice is now treated as not chosen, so its setting takes the default it would have had, where it used to be written as `null`. The choices are checked even when `.planning/config.json` already exists, which used to report `already_exists` without looking at them. `--dry-run` is now honored: it prints the config that would be created and writes nothing, where it used to be ignored and the file written anyway. Any other flag, or a second positional argument, is refused.
