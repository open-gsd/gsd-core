**Secret-read guard now blocks git command lines that run a command printing `.env`** — command-valued `-c` keys and the same config set in the environment on the command line (`GIT_CONFIG_*`, `--config-env`, `GIT_EDITOR`-style variables), aliases, subcommand options and trailing commands, `ext::` URLs and ssh's `ProxyCommand`-style options could run `cat .env` unchecked, as in `git -c sequence.editor='cat .env; true' rebase -i` or `git rebase -x 'cat .env'`, and a command too large to check now blocks as `command-too-complex` instead of crashing the hook. The guard also reads a shell's `-c` script wherever `-c` sits among its options, a script fed to `source` or a shell through `/dev/stdin`, what `printf` and `echo -e` write into a shell or `xargs`, `dd if=`, a `time VAR=…` prefix, and a command behind a wrapper it does not list (`caffeinate git -c core.fsmonitor='cat .env' status`, `docker exec c sh -c 'cat .env'`). A `BASH_ENV` or `ENV` value naming `.env` is now a read wherever it is assigned, and one naming `/dev/stdin` or `/dev/fd/N` makes the command's stdin a script (#6445). A filter stage such as `head`, `sort` or `grep` between a producer and a shell now fails closed on any mention of a protected name, so `printf 'cat .env' | head | bash` is blocked, and so is `echo 'echo .env' | sort | bash`. Words `xargs` hands to `dd` are read for `if=`, and every word `xargs` reads is judged split at blanks (`echo 'x if=.env' | xargs dd`). A read-write redirect (`cat <> .env`) is a read, and `npx -c` and `npm exec -c` scripts are scanned, also behind an unlisted wrapper.
