**Secret-read guard now blocks git command lines that run a command printing `.env`** — command-valued `-c` keys and the same config set in the environment on the command line (`GIT_CONFIG_*`, `--config-env`, `GIT_EDITOR`-style variables), aliases, subcommand options and trailing commands, `ext::` URLs and ssh's `ProxyCommand`-style options could run `cat .env` unchecked, as in `git -c sequence.editor='cat .env; true' rebase -i` or `git rebase -x 'cat .env'`, and a command too large to check now blocks as `command-too-complex` instead of crashing the hook. The guard also reads a shell's `-c` script wherever `-c` sits among its options, a script fed to `source` or a shell through `/dev/stdin`, what `printf` and `echo -e` write into a shell or `xargs`, `dd if=`, a `time VAR=…` prefix, and a command behind a wrapper it does not list (`caffeinate git -c core.fsmonitor='cat .env' status`, `docker exec c sh -c 'cat .env'`). A `BASH_ENV` value naming `.env` is now a read for any command run with it set (a bash that command starts sources it), an `ENV` value where a shell runs, and one naming `/dev/stdin` or `/dev/fd/N` makes the stdin a script (#6445). A filter stage such as `head`, `sort` or `grep` between a producer and a shell now fails closed on any mention of a protected name, so `printf 'cat .env' | head | bash` is blocked, and so is `echo 'echo .env' | sort | bash`. Words `xargs` hands to `dd` are read for `if=`, and every word piped into `xargs` is judged split at blanks (`echo 'x if=.env' | xargs dd`), a search or listing tool's too since grep prints its pattern and find/ls print matching names, so `grep -r 'API_KEY .env' src | xargs cat` is blocked. A read-write redirect (`cat <> .env`) is a read, and `npx -c` and `npm exec -c` scripts are scanned, also behind an unlisted wrapper. Every command inside a `( … )` or `{ …; }` group piped into a shell is read, failing closed, so `(echo 'cat .env'; true) | sh` is blocked. npm's command-valued config (`call`, `shell`, `browser`, `editor`, from a long option of any prefix, an `npm_config_*` variable, or EDITOR/VISUAL/SHELL/ComSpec for `npm edit`/`explore`), `npm explore`'s words, `pnpm exec`/`dlx` in shell mode and `yarn exec` are scanned as scripts. Cost: a segment piped into a chain of 15 or more nested runner launches (`echo x | caffeinate npm exec -- nice npm exec -- …`) is blocked as `command-too-complex`, text naming a protected file that is piped through a filter (into a shell or `xargs`) or out of a group is blocked even when nothing reads it (`echo 'echo .env' | sort | bash`), and so is a search whose pattern or arguments name one, piped into `xargs` (`grep -rl 'TODO .env' src | xargs wc -l`), and an escaped here-string `xargs` reads (`xargs cat <<< '\x2eenv'`). A decoded `printf '\x2eenv' | xargs cat` is blocked.
