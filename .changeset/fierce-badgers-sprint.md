**A verification report with a status outside `passed | gaps_found | human_needed` is now a hard error, and a stale phase re-verifies instead of looping** — `status: verified` (or `Passed`, `stale`, a number) used to route as `unknown` to `/gsd-execute-phase`; every command that reads the report now stops with `verification_status_invalid` naming the file, the value, the accepted values and the recovery (set the report's `status:` or delete the report and re-run verification), and `/gsd-health` reports it as `W030`. Case-folded and legacy statuses (`Passed`, `pending`, `partial`) that `phase complete`'s warning pre-scan and `audit-uat` used to fold into a known status hard-error the same way. A stale report has one route: `/gsd-verify-work` now runs the same regeneration step as `/gsd-execute-phase` so the phase ends `passed` (a `missing` report on a phase that is not fully executed still blocks with `/gsd-execute-phase` instead), and a phase directory that does not exist reads `phase_dir_not_found` with no next command instead of sending you to re-execute it. `verification status` and `planning inspect` gain an additive `route` field (the bare command the status routes to) and `init *` gains `verification_route`; the `unknown` status no longer exists (#5118).
