**A named project (`GSD_PROJECT`) or a workstream now reads, writes and commits its own planning files in the workflow and agent shell steps that used to name the root project's** — shell-fence lines named root `.planning/` files (STATE.md, ROADMAP.md, REQUIREMENTS.md, PROJECT.md, config.json, `phases/` and their checkpoints, `quick/`, milestone archives), so under another scope they read the root project's context, archived its phases, edited its config, or committed nothing while gsd-tools had updated the scoped files. They now use the paths gsd-tools resolves (init `*_path`/`*_dir` fields, `config-path` and its directory for globs, stopping when that cannot be resolved); the state, roadmap, requirements and phase writers in those steps forward `--ws`; `/gsd-resume-work` and `/gsd-pause-work` use the selected scope's phase checkpoints and never another scope's (a named project or workstream with no phases yet lists none); `/gsd-milestone-summary <version> --ws <name>` no longer folds the `--ws` token into the version; the regression gate reads this scope's other phases, selected as before; `/gsd-settings` reads and writes one scope's config; `/gsd-audit-milestone` writes its report into the selected scope's planning directory, where `/gsd-complete-milestone` now reads it, and hands the integration checker full phase directory paths; and `/gsd-code-review --fix` honours the scoped `workflow.use_worktrees`. Executors spawned by `/gsd-execute-phase` receive the run's workstream token, so their state, roadmap and requirements updates land in the scope their commit stages, and `/gsd-next`'s incomplete-phase scan reads that same scope. `gsd-tools config-path` now prints forward slashes on every platform, matching init's `config_path`. `HANDOFF.json`, the root `.continue-here.md`, `RETROSPECTIVE.md` and `reports/MILESTONE_SUMMARY` stay one shared root copy for every scope. The root project's paths are unchanged, and worktree executors receive those paths relative to the project root, so their writes and commits stay in their own worktree. Steps that name `.planning/codebase/` or `.planning/intel/` directly are not covered yet. (#5861)
