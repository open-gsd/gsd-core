**plan-phase's stall watch now waits for the planner and plan-checker to actually return** — it no longer reports them finished at its first check because their own prompt or definition mentions the return markers, and a finished plan revision now continues instead of always ending in the stall menu. Each watched spawn writes its complete return (marker line first) to a per-dispatch return receipt under the phase's gitignored `.gsd-returns/`, renamed into place so it is never half-written, and plan-phase routes on that file without waiting for the host's completion result; the plan-checker writes its receipt through its shell and keeps its read-only tool set, so no host's tool grants change. No receipt is created unless the phase directory and the project root are absolute paths in the form plan-phase's init emits (no empty, `.` or `..` component, no trailing separator (a project root at the filesystem root aside), no quote, `$`, backtick, `<`, `>` or ASCII control character, and no backslash in the phase directory), and none for a symlink, dangling or not, at the phase directory or at any path component from the phase directory up to and including its nearest existing ancestor (a link above that ancestor is accepted only when the resolved path stays under the project root and outside `.git`); one that resolves outside the project root plan-phase resolved (for example through a symlinked parent), or a project root or ancestor that does not resolve; the project root itself; anything inside `.git` below the project root, in any letter case and under the names Windows reads as `.git` (a trailing dot or space, `GIT~1`); or a `.gsd-returns` directory or its `.gitignore` that is a symlink, resolves elsewhere, is not a regular file or not exactly the `*` line plan-phase writes, or cannot be created, read or written. A one-line stderr reason names the refusal, and the watch then ends on the agent's own completion result or as stalled. Where a sandbox refuses the checker's shell write (Codex `read-only`), the checker's watch ends the same way. (#5182)
