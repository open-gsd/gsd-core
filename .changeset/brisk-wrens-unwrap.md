**The Bash secret-read and debugger-spawn guard now reads the command inside an `env -S` string** — `env -S 'cat .env'` and `env -S 'claude --agent gsd-debugger'` were allowed, because the string was skipped as the option's value. The guard now splits it the way GNU env does and checks the command it runs. It also reads the string with each `${NAME}` empty, as env expands a name that is not set (`env -S 'cat .e${Z}nv'`), and the way macOS and FreeBSD env (a backslash before a blank is that blank) and uutils env (a backslash-newline removed, and a comment ended by a newline rather than ending the string) split it. A string that splits out of another split string more than three levels deep is denied as `split-string-too-deep`. The string is also still read as before, skipped as the option's value, and any reading's hit denies, so the change adds denials and removes none. The guard's path-segment helper now strips trailing `/` and `\` with a loop instead of a regex that was quadratic on a long run of them, since a split string can make such a run a command word and the regex outlasted the hook's timeout. (#5514)
