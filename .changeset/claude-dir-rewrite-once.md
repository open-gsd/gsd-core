**Installs into a nested or unusually named config directory keep correct paths on every runtime** — the installer rewrote `~/.claude` references in several passes, and the converters that run afterwards (agents, the `gsd-core/` spec tree, OpenCode and Kilo commands and skills, command bodies, the Codex agent TOML) scanned the emitted prefix again, so a `--config-dir` such as `~/.claude/profiles/work`, `~/.claude.d` or `~/.copilot/work` was rewritten inside its own output, and `$&` in a config dir was expanded into the text around it. A Kilo install wrote paths like `.../profiles/work/profiles/work/gsd-core`, an OpenCode install wrote paths like `.claude/~/.config/opencode/x`, and a Codex agent TOML got `~/.codex` in place of `$&`. Each reference is now rewritten once and the emitted prefix is shielded from every later converter, for Kilo, OpenCode, Codex, Cline, CodeBuddy, Hermes, Qwen, Windsurf, Kimi, Trae agents and spec tree, Augment commands, and the Copilot and Antigravity `@` includes for a config dir under their own default home. Intentional changes to default-install output: (1) Windsurf global installs turned `~/.devin/skills/x` and `$HOME/.devin/skills/x` into `~/$HOME/.codeium/windsurf/skills/x` and `$HOME/$HOME/...`; they now give `$HOME/.codeium/windsurf/skills/x`. (2) Claude Code's own files such as `~/.claude.json`, `$HOME/.claude.json`, `~/.claude-plugin` and `./.claude-plugin` were rewritten into nonexistent names like `$HOME/.cline.json`; they now stay unchanged. (3) A Trae local install wrote `$HOME/.trae/...` and `~/.trae` paths, including `@$HOME/.trae/gsd-core/...` includes, into its skills, which point at the global directory; they now point at the project's `.trae/`. A comparison of real default installs of all 18 installable runtimes, global and local, against the previous build found no other difference in the installed files. (#5715)
