**`npm test` fails when product code writes a file named `STATE.md` outside the STATE.md write seam, or through the seam without the STATE.md lock** (#5120, epic #4629): a test-time check of the written path's value that also holds a rename or copy of a `STATE.md` to the lock on both ends. The STATE.md writers it found, and the ones review found, now hold the lock: workstream create, migrate and complete (and their rollbacks; migrate and complete can wait on two STATE.md locks in turn, 30 s each; `workstream complete` adds `workstream_dir_left` to its output when the workstream directory is still there afterwards, and a failed migrate or complete names a directory it leaves behind), `gsd-tools frontmatter set` and `frontmatter merge` on a file named `STATE.md` (they now wait for a held STATE.md lock, take over a live holder's lock older than 60 s and a dead holder's lock, refuse a non-regular STATE.md, and fail with the lock error in a read-only directory), `quick-batch complete` (now through `readModifyWriteStateMd`, the `quick-tasks-append` route, so its frontmatter is synced with the body, keeping `progress.*`, and it waits for a held STATE.md lock while holding the planning lock), the `from-gsd2` import, the `gsd-tools roadmap upgrade --apply` rollback (which restores STATE.md byte-exactly, under the lock, only while it still holds what the migration wrote, and also names a file whose restore failed), and MCP `gsd_write_state` (the `filesystem` stateIO adapter), which writes a `STATE.md` destination through the seam, so it lands the seam's normalized markdown, waits for a held lock, refuses an existing `STATE.md` that is a symlink, a FIFO, a device, a socket, a directory or a hard link with a tool error, and fails at once on a `STATE.md` path whose directory is missing. ADR-3408 section 8.3 and ADR-4629's guard roster are amended to match.
