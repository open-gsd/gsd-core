**The `opus` tier now resolves to Claude Opus 5 on Anthropic-compatible runtimes** — `query resolve-model` / `resolve-execution` return `claude-opus-5` (claude, copilot, pi) and `anthropic/claude-opus-5` (opencode, hermes, kilo) where they previously returned Opus 4.8, so the 22 catalog agents whose `golden` tier is `opus` — including `gsd-planner`, `gsd-roadmapper`, and `gsd-executor` — run on the current generation with no config change and no price change ($5 / $25 per MTok, 1M context). The `anthropic` provider preset gains a genuine third rung instead of advancing wholesale: only `opus.high` moves to `claude-opus-5`, while `medium` (`claude-opus-4-8`) and `low` (`claude-opus-4-5`) stay exactly where they are, so nobody loses a model they can pin to. `sonnet.high`, which deliberately borrows the opus tier's top model, moves with it. **Opus 5 draws from its own rate-limit bucket rather than the combined Opus 4.x pool**, so an account provisioned against Opus 4.x limits may see 429s on this new default. On the `claude` runtime you cannot pin an older Opus generation: the tier resolves through Claude agent aliases, so an older-generation ID in `model_overrides` or the `anthropic` preset warns and falls back to the tier (`claude-opus-4-8` is no longer a built-in tier default). To hold `claude-opus-4-8`/`claude-opus-4-5`, run a non-Claude Anthropic-serving runtime (`opencode`, `hermes`, `kilo`, `copilot`, `pi`) and set the `anthropic` preset at `budget: "medium"`/`"low"`, where GSD emits the ID verbatim. Runtimes that bake the resolved model into installed agent artifacts (Codex, OpenCode, Kilo) keep emitting the old ID until the user reinstalls or updates. (#2683)
