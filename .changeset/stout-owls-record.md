**The dispatch-isolation record now states who decided it, so a re-query knows what it may re-derive** — the resolver re-derives some isolation decisions on every call (the `use_worktrees` opt-out since #3737, the #683 worktree base check since #4222) while three dispatch sites compute a degrade it structurally cannot reconstruct and record it with `--force-isolation none` (#4561). Both are written as a fresh, in-scope `none`, so on the old record shape a later plain query could not tell them apart: holding every such record made a re-derived degrade stick after the repository caught up, and holding none of them clobbered the decisions only the caller could make. The record carries its provenance, and the hold keys on that instead of on value-plus-freshness — a `resolver` decision is re-evaluated live, a `caller` decision is honoured. A record written without the field (a pre-upgrade `gsd-tools` still in flight) reads as the caller's, because holding a re-derivable degrade costs one sequential run while clobbering the caller's makes the isolation guard refuse the dispatch outright. Relatedly, the resolver no longer re-derives a base-check degrade for a root that is not a git repository at all: there is no HEAD to compare against a fork base, and #4734's guard fallback already allows that dispatch.
