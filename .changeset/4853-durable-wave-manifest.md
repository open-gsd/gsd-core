**Interrupted `execute-phase` waves leave durable, discoverable worktree manifests** — wave worktree manifests now reside at deterministic phase-scoped paths (`{phase_dir}/wave-{N}-manifest.json`) instead of an ephemeral random file under `$TMPDIR`. If a wave crashes, times out, or is interrupted, the manifest remains discoverable on disk or queryable via `gsd_run query worktree.manifest-path`, so operators can reconcile the recorded worktrees. Completed wave cleanup automatically removes the manifest file. Manifests are ephemeral runtime records holding machine-local paths; `gsd_run query commit` automatically excludes wave manifests from staging and commits under `commit_docs: true`. Wave dispatch and cleanup-wave refuse git-tracked manifests with a FATAL diagnostic and `git rm --cached` guidance (#4853). Wave numbers are bounded to 1–999 so the commit pathspec and the parser agree. An empty manifest still fails closed; `cleanup-wave --allow-empty` reconciles one left by a wave interrupted before any executor was recorded. Executors still running when a wave dies are not in the manifest, so their `worktree-agent-*` branches need manual review. `isContainedIn`'s Windows fallback now normalizes both paths before the case-insensitive prefix check, so a mixed-separator `..` is not reported as inside the root, a trailing separator still contains its children, and UNC paths compare case-insensitively.
