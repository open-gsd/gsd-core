**`roadmap.annotate-dependencies` now rewrites an existing wave annotation when a replan changes the waves** — the command used to return early once a phase's Plans block carried `**Wave N**` headers or a cross-cutting constraints block, so ROADMAP.md kept the old grouping and could contradict a plan's `depends_on`. It now rebuilds the block from the plans' current `wave` frontmatter; an unchanged re-run still writes nothing and returns `updated: false`. Generated constraint headings now carry an invisible `<!-- gsd:generated -->` marker, and bullets directly under that heading are machine-owned (regenerated each run, with a stderr warning and a `dropped_generated_constraints` list in the JSON when one matching no current plan truth is dropped; put your own after a blank line); a pre-existing block without it is rebuilt: bullets equal to a current plan truth are regenerated, and any other bullet is kept with a stderr warning and a `stale_legacy_constraints` list in the JSON so a reworded constraint is reported, not silently left behind. A Plans list split by an unrecognised checklist row (`- [  ]`, `* [ ]`) or an empty wave header is left untouched: stderr warns and the JSON carries `skipped: "unrecognised_checklist_row"`. (#5321)
