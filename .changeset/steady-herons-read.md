**`config-get commit_docs` now reports the value the runtime uses** — after `config-set planning.commit_docs false`, `config-get commit_docs` read "Key not found", so the workflow gates that read it (`/gsd-quick`'s pre-dispatch commit, `/gsd-new-milestone` and eight others) fell back to committing `.planning/` files. `commit_docs` and `search_gitignored` now read back the resolved value under either spelling (`commit_docs` or `planning.commit_docs`), including a gitignored `.planning/` resolving `commit_docs` to false, so the `/gsd-settings` integrations screen also shows a nested `planning.search_gitignored: true` correctly. Reading the nested spelling can therefore print a value other than the one written there: with both `commit_docs: true` and `planning.commit_docs: false` in `config.json`, `config-get planning.commit_docs` prints `true`, because the flat key wins and that is the value the runtime applies. For these two settings `--default` no longer applies: the read prints the resolved value and exits 0, so with no `.planning/` directory `config-get commit_docs --default false` now prints the default, `true` unless `~/.gsd/defaults.json` sets it, where it printed `false`. A `config.json` that is not valid JSON or cannot be read still fails the read, `--default` or not. (#5470)
