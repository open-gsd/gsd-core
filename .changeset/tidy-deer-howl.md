**The secret-read guard reads a Bash word's brace groups as the words bash makes of it** — `cat {.env,x}`, `cat .e{n,x}v`, `cat {,.env}`, `grep .env{,}` and the same inside `bash -c '…'` were allowed and read `.env`, because the guard judged the unexpanded word. Each unquoted brace group is now expanded the way bash 5.2 does (nesting, cross products, empty alternatives, sequences) and every resulting word is judged like a plain one; quoted, escaped and comma-less groups stay literal. A word making more than 64 words is blocked as too complex unless it provably cannot change a verdict, so `for i in {1..120}`, `mkdir d{1..100}`, `X={1..100}` and `arr=({1..100})` stay allowed; past the budget, a word of letters only (`cat {a..z}{a..z}`), one on a command that reads its operands by position (`grep pat {1..70}`, `cp {1..70} b`, `git add {1..70}`, `find {1..70}`, `git show HEAD~{1..70}`) or one that `echo` or `printf` prints (`echo {1..100}`, `printf '%s\n' {1..100}`) is now blocked, and a command of many brace words is blocked as too complex from about 326,000 characters of `{1..64}` words. zsh's `{c1..c2}` of any two characters, quotes removed, is read as the characters between them too, so `cat {-..9}env` and `cat {a...}env` are blocked, and so is zsh's numeric range with a bare `-` read as 0 (`grep -m {-..10} .env` makes `.env` a file). A group that a CR or a `<( )` or `>( )` substitution runs into before it closes, wherever it sits in the group (`cat {.env,<(echo })}`, `cat {<(true),.env}`, `cat {x\r,.env}`, which bash reads as `.env`), and a brace word that runs into a `(` an extglob or zsh glob takes on (`cat {.env,x}?(y)`, `cat {.env,(x)}`), are blocked with the new code `brace-word-unreadable`, benign ones such as `diff {a,<(sort b)}`, `cat {a}<(true)` and `cat {a,b}@(x)` included. A project-exempt file now keeps its exemption only if the line reads only with its brace groups made into words as well (`sort {-o,/tmp/out} .env.production` writes) (#6142).
