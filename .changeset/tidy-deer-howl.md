**The secret-read guard reads a Bash word's brace groups as the words bash makes of it** — `cat {.env,x}`, `cat .e{n,x}v`, `cat {,.env}`, `grep .env{,}` and the same inside `bash -c '…'` were allowed and read `.env`, because the guard judged the unexpanded word. Each unquoted brace group is now expanded the way bash 5.2 does (nesting, cross products, empty alternatives, sequences) and every resulting word is judged like a plain one; quoted, escaped and comma-less groups stay literal. A word making more than 64 words is blocked as too complex unless it provably cannot change a verdict, so `for i in {1..120}`, `echo {1..100}` and `mkdir d{1..100}` stay allowed; past the budget, a word of letters only (`cat {a..z}{a..z}`) or one on a command that reads its operands by position (`grep pat {1..70}`, `cp {1..70} b`, `git add {1..70}`, `find {1..70}`, `git show HEAD~{1..70}`) is now blocked, and a command of many brace words is blocked as too complex from about 326,000 characters of `{1..64}` words. zsh's `{c1..c2}` of any two characters, quotes removed, is read as the characters between them too, so `cat {-..9}env` and `cat {a...}env` are blocked, and so is zsh's numeric range with a bare `-` read as 0 (`grep -m {-..10} .env` makes `.env` a file). A group a `<( )` or `>( )` substitution runs into before it closes (`cat {.env,<(echo })}`, which bash reads as `.env`) is blocked as too complex, benign ones such as `diff {a,<(sort b)}` included (#6142).
