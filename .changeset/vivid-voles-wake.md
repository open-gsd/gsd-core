**The secret-read guard no longer lets `grep`, `egrep`, `fgrep`, `rg` or `jq` read a secret file through words it cannot see, nor `xargs` hand its command file names the guard never saw** — since #6247, `echo '-e KEY' | xargs grep .env` was allowed and read `.env`, and so were `sh -c 'grep .env "$@"' _ -e KEY`, `X='-e K'; grep .env $X`, `grep .env *` (a file named `-eKEY` turns `.env` into a file), `export GREP_O*; grep .env` (a file named `GREP_OPTIONS=-eKEY`), `alias grep='grep -eKEY'`, `grep --label .* .env` and `POSIXLY_CORRECT=1 grep -n KEY . --exclude .env`, while `printf '.env\n' | xargs cat`, `xargs cat <<< .env`, `sh -c 'xargs cat' <<< .env`, `printf '.envx' | xargs -d x cat` and `xargs -a list cat` read files named where the guard did not look. A search tool now keeps no pattern or exclusion exemption when it is run by `xargs`; when the command holds a command substitution, an `alias`, or a `$` expansion that is neither inside single quotes nor after the list separator ending the tool's command (an `eval`, `source`, `.`, `<( )`, function, loop, `set --`, `trap`, heredoc or comment anywhere keeps it whole-command); when it sets `GREP_OPTIONS`, `RIPGREP_CONFIG_PATH` or `POSIXLY_CORRECT`, by name or through a glob that can spell one; when an unquoted glob, brace or `~` can add or shift its words; or, for a separate-value exclusion such as `--exclude .env`, when the exclusion follows an operand. xargs options are read the way GNU and BSD xargs read them (`-i`, `-l`, `--max-args 1`, BSD `-J`/`-R`/`-S`, `-d`, `-0`), so a shell or `watch` sub-command behind one is scanned; a here-string, heredoc, piped `echo` (judged as written and with its escapes read) or `printf` (`%s` filled, `\n` and `\0` read) is read as xargs's words, split at its delimiter or unquoted as xargs unquotes them, also when a group, subshell, shell or function running xargs is given it; words from a source the guard cannot read (`< list`, `<>`, `<&3`, such a redirect on an enclosing group, on `exec` before xargs, on the shell running xargs or on a call to a function the command defines, `-a list`, `-a <(…)`) are blocked as `xargs-input-unseen`, those a `printf` writes with an escape or conversion other than `%s`/`%%` as `xargs-stdin-unrendered`, and words split at a `-d` value it cannot decode as `xargs-delimiter-undecodable`, unless the command reads nothing (`xargs echo`) or is a shell whose `-c` script is literal and takes none of them. The cost: shapes that read nothing are blocked too, such as `ls | xargs grep -n token --exclude=.env`, `grep .env *.md`, `grep -rn x --exclude=.env "$DIR"`, `grep -rn x{1..3} --exclude=.env .`, `grep -rn ~root --exclude=.env .` (and `~+`), `echo $HOME; grep -r x --exclude=.env .`, `jq '.env.X' "$HOME/settings.json"`, `grep -n KEY . --exclude .env`, `xargs cat < filelist`, `xargs -0 cat < <(find . -print0)`, `xargs -a files wc`, `sh -c 'xargs cat' < filelist`, `f() { xargs cat; }; f < filelist`, `{ { xargs cat; } <<< a; } < filelist` (overlapping redirects fail closed) and `printf '%d\n' 1 | xargs cat`. `grep .env docs/*.md`, a quoted regex, `grep -rn '$HOME' --exclude=.env .`, `grep -rn x --exclude=.env . ; echo $?` and `--exclude=.env` before or after an operand stay allowed, and so does `cat list | xargs cat`, whose piped names the guard cannot read either (not covered: closing it would deny every `find … | xargs` and `git ls-files | xargs`).
