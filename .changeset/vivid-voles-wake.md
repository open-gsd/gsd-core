**The secret-read guard no longer lets `grep`, `egrep`, `fgrep`, `rg` or `jq` read a secret file through words it cannot see** — since #6247, `echo '-e KEY' | xargs grep .env` was allowed and read `.env`, and so were `sh -c 'grep .env "$@"' _ -e KEY`, `X='-e K'; grep .env $X`, `grep .env *` (a file named `-eKEY` turns `.env` into a file), `grep --label .* .env` and `POSIXLY_CORRECT=1 grep -n KEY . --exclude .env`. A search tool now keeps no pattern or exclusion exemption when it is run by `xargs`; when the command holds a `$` expansion, a command substitution, or `GREP_OPTIONS`, `RIPGREP_CONFIG_PATH` or `POSIXLY_CORRECT`; when an unquoted glob, brace or `~` can add or shift its words; or, for a separate-value exclusion such as `--exclude .env`, when the exclusion follows an operand. xargs options are read the way GNU and BSD xargs read them (`-i`, `-l`, `--max-args 1`, BSD `-J`/`-R`/`-S`), so a shell or `watch` sub-command behind one is scanned. The cost: shapes that read nothing are blocked too, such as `ls | xargs grep -n token --exclude=.env`, `grep .env *.md`, `grep .env "$f"`, `echo $HOME; grep -r x --exclude=.env .`, `jq '.env.X' "$HOME/settings.json"` and `grep -n KEY . --exclude .env`; `grep .env docs/*.md`, a quoted regex and `--exclude=.env` before or after an operand stay allowed.
