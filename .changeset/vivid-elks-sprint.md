**Closing a milestone no longer goes through while a capability still reports open work** — before, `/gsd-complete-milestone` archived the roadmap even when a blocking `ship:pre` gate still failed; now `milestone complete --confirm` refuses with `milestone_gate_blocked`, `--dry-run` and `/gsd-audit-milestone` run blocking `ship:pre` gate commands, and gate commands read `GSD_PHASE_*` environment values, so the old `${PHASE_*}` spelling is refused and `"${GSD_PHASE_NUMBER}"` replaces it, and a placeholder not provably in plain double quotes is refused too (for example unquoted, single-quoted `'${GSD_PHASE_NUMBER}'`, inside the text `eval`, `trap` or `sh -c` parses again, or in a command that runs `xargs` without `-0` or `-d`; `docs/reference/gate-predicates.md` lists the forms), so assign it to a variable first and double-quote the assignment and every later use; the `--dry-run` JSON gains `would_refuse` and `gate_warnings`, and the beads ship gate (gsd-beads-i7e7) must move to the `GSD_PHASE_*` names. (#5482)
