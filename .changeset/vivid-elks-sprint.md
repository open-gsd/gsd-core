**Closing a milestone no longer goes through while a capability still reports open work** — before, `/gsd-complete-milestone` archived the roadmap even when a blocking `ship:pre` gate still failed. `milestone complete --confirm` now re-runs each such gate once per milestone phase and refuses, listing every blocking gate; `--force` does not bypass it. `--dry-run` and `/gsd-audit-milestone` preview the same open work, so they now run the gate commands (30 s per gate per phase by default), and the `--dry-run` JSON gains `would_refuse` and `gate_warnings`. A command gate reads the phase values from the environment variables `GSD_PHASE_NUMBER`, `GSD_PHASE_DIR` and `GSD_PHASE_REQ_IDS`, so a directory name with shell syntax runs no command. Breaking: the old `${PHASE_NUMBER}`, `${PHASE_DIR}` and `${PHASE_REQ_IDS}` spelling is refused in every quoting form with a message that names the replacement, so change `'${PHASE_NUMBER}'` to `"${GSD_PHASE_NUMBER}"`. The beads ship gate migrates to `$GSD_PHASE_NUMBER` (gsd-beads-i7e7). When the milestone window cannot be resolved, a blocking `onError: halt` gate refuses the close. (#5482)
