**`worktree.reap-orphans` now removes leftover `.claude/worktrees/agent-*` directories that git no longer tracks** — a Claude Code worktree whose teardown did not finish (no `.git` file, its admin entry pruned) was invisible to the sweep, which answered `reaped: 0` while it sat on disk with its `node_modules`. Such a directory is removed only on positive evidence that it is harness residue of this repository: a real, non-empty directory with no `.git` entry, not listed by git, older than the five-minute guard, with a harness branch (`agent-<id>` or `worktree-agent-<id>`), no git-tracked file and no repository inside it, under a `.claude/worktrees` that is not a link; any other candidate is reported and left. `/gsd-quick`, `/gsd-quick-batch` and execute-phase's startup sweep now keep the command's stderr (they used to discard it), so a summary reaches the agent transcript: removed directories by escaped, capped name, kept ones counted by reason. A sweep run from a linked worktree says it did not look, the output gains a `scan` field saying which locations were read, and wave cleanup blocks an entry whose directory is such residue as `worktree_unregistered` instead of `branch_mismatch` (#4941).
