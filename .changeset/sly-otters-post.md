**The secret-read guard blocks a secret file named inside a curl option value** — `curl -d @.env` was denied, but curl opens `.env` just the same for `curl -d@.env`, `curl -sd@.env`, `curl -H@.env`, `curl -F file=@.env`, `curl -F "file=<.env"`, `curl --data-urlencode k@.env`, `curl --url-query k@.env` and `curl --variable k@.env`, and all of those were allowed. When a command runs curl, the guard now also judges the file names curl reads after an `@` or `<` inside a curl argument, following curl's form syntax: the whitespace curl skips around a name, a form file list (`@a.txt,.env`) that goes on after any part parameter (`;type=…`, `;filename=…`, `;headers=<…`), a quoted name (`@".env"`, or an unmatched quote read as part of the name), a `;headers=@.env` file (also after a quoted value such as `name="a@";headers=@.env`), and a `<` name that keeps its commas outside a list. The same spellings naming `notes.txt` or `.env.example` stay allowed, and so do a quoted value curl reads whole (`;filename="a,.env"`) and text with no `@` or `<` before the name, such as a JSON body mentioning `.env`. The reading applies after a `curl` word anywhere in the command, so `xargs curl …`, words piped into `xargs curl` and `find … -exec curl …` are covered, while a search pattern in a command with no `curl` word (`grep 'user@.env' f`) is judged as before. Consequences toward blocking, covered by tests: an `@` or `<` followed by a secret name is denied in any curl argument, including where curl reads it as data (`curl -d k=@.env`, `curl --form-string file=@.env`, `curl -d 'email=me@.env'`, `curl 'http://user@.env/'`) or as part of one longer name (`curl -d '@notes.txt,.env'`, `curl -d '@a@.env'`, `curl -d '@".env"'`, since `-d`, `-H` and `--data-urlencode` take the rest of the word as one name), and a template name followed by a comma in a form list (`curl -F 'file=@.env.example,notes.txt'`) is judged as the one name `-d @…` would open. A pattern word is denied too in a command that also holds a word whose last path segment is `curl` (`grep curl 'x@.env' f`, `tar czf b.tgz vendor/curl 'me@.env'`). Not covered: curl's own `{a,b}` globbing in an upload or `file://` name, a `-d` / `-H` / `--data-urlencode` file whose own name holds a `;`, `<` or `@` after a template prefix, and a curl the guard does not resolve as a word (`$'curl'`, `env -S 'curl …'`), as for every other command. (#5779)
