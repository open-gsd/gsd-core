**The secret-read guard blocks a secret file named inside a curl option value** — `curl -d @.env` was denied, but curl opens `.env` just the same for `curl -d@.env`, `curl -sd@.env`, `curl -H@.env`, `curl -F file=@.env`, `curl -F "file=<.env"`, `curl --data-urlencode k@.env`, `curl --url-query k@.env` and `curl --variable k@.env`, and all of those were allowed. The guard now reads each curl argument the way curl does, without a table of which option takes which value: as a `-F` value, by a port of curl's form parser (`src/tool_formparse.c`) run under each grammar curl has shipped (through 8.11, 8.12, and 8.13 on), which finds every file of an `@` list, a `<` file and a `;headers=@` or `;headers=<` file, with curl's quoting, escapes, whitespace and `type=` parsing; and as a value of the options that read `@file` (`-d` and the other `--data` forms, `--json`, `-H`, `-w`, `--data-urlencode`, `--url-query`, `--variable`), whose file is the rest of the value; and, for the value of `--cert`, `--proxy-cert` or `-E` only (also spelled `--expand-cert`, `--cert=…`, in any case as curl 8.5 reads long names, or filled through `xargs` where the option is the last word or its value holds the replace string), as `file:password`, by a port of curl's own reading (`src/tool_getparam.c`: a `\:` escape, a `pkcs11:` URI, a Windows drive letter's colon). A value attached to short options (`-d@.env`, `-sd@.env`, `-Ffile=@.env`) is read the same way. The same spellings naming `notes.txt` or `.env.example` stay allowed, and so do a quoted value curl reads whole (`;filename="a,.env"`), data curl sends as text (`-d 'email=me@.env'`, a JSON body mentioning `.env`) and a name curl opens whole (`-d '@notes.txt,.env'`). The reading applies to curl's own arguments: where curl is the command (also behind `sudo`, `env`, `timeout` and the other wrappers the guard unwraps), where it is the command `xargs` runs (its options read as GNU `xargs` reads them) or the command of a `find` or `bfs` `-exec`, `-execdir`, `-ok` or `-okdir` action (`xargs -i sudo curl …`, `find … -exec curl … \;`), after the first `curl` word under a command whose job is to run another (`watch`, `ionice`, `strace`, `parallel`, `torsocks`, `pkexec`, `wsl`, `npx` and others in the guard's list), or past the subcommand or option such a command runs one by (`uv run`, `npm exec`, `op run --`, `kubectl exec`, `docker exec`, `docker compose run`, `fd -x`; a container runner's `--entrypoint=curl` and a `curlimages/curl:<tag>` image name curl too), a subcommand counting only as the command's first operand past its options (`kubectl get exec curl …` runs no curl), also with a Windows `.exe` or `.cmd` name (`docker.exe`, `npx.cmd`), and for words piped into `xargs curl`. A `curl` word that no command runs is an ordinary operand, so a search pattern beside it (`grep curl 'x@.env' f`, `apt-get install curl 'me@.env'`, `uv pip install curl 'me@.env'`) is judged as before, as it is in a command with no `curl` word (`grep 'user@.env' f`). Consequences toward blocking, covered by tests: a value read as a `-F` value or as an `@file` value where its option reads it another way (`curl -d k=@.env`, `curl --form-string file=@.env`, a URL's `user@` part in `curl 'http://user@.env/'`), the words after the first `curl` word under a listed command that runs something else (`watch grep curl 'x@.env' f`), an option's value, or a subcommand after an option, taken for the launcher's subcommand when a later word runs a command (`docker --context run pull curl 'x@.env'`, `docker --debug pull run curl 'x@.env'`), yarn's `workspace` group read as running its command (`yarn workspace foo add curl 'x@.env'`), and a word read as a cert value where another option takes it (`curl -d --cert .env:pw`, `curl -dE.env:pw`). Not covered: curl's own `{a,b}` globbing in an upload or `file://` name, a name curl builds from `--variable` values in an `--expand-*` option (`curl --variable f=.env --expand-data '@{{f}}'`, as the shell's `F=.env; cat "$F"` is not covered), a file named inside a curl config file (`-K cfg`, or `-K -` read from stdin, as in `echo 'data=@.env' | curl -K -`), the quote and backslash removal `xargs` applies to the words piped into it and the shell re-reading of a command given to `watch`, `parallel` or `sem`, and a curl the guard does not resolve as a command: spelled so it is not a word (`$'curl'`, `env -S 'curl …'`, a Nix installable `nixpkgs#curl`), run by a command, or a subcommand of a listed one, the guard does not list as running another, or on another host (`ssh host curl …`) or through more than three launchers, or given to a launcher as one string (`watch 'curl …'`), as for every other command.
