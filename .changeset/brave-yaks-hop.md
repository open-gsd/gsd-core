**The GSD plugin now loads on OpenCode 2.x, and its guards now actually block on OpenCode 1.x and Kilo** — OpenCode 2.x rejected the plugin at every start with `Missing key at ["default"]["effect"] / ["default"]["setup"]`; the plugin now also exports the 2.x `setup` entrypoint, and on 2.x the tool guards (including on `shell` and `patch` calls), `GSD_DIR` in shells, the compaction context, the session-start hooks and the config reload run through the same hooks 1.x uses. On OpenCode 1.x and on Kilo, which ships the same plugin, the guard hooks never ran, because each hook subprocess relaunched the host binary instead of running the hook as JavaScript; hooks now run as JavaScript under the host's Bun, so secret reads and cross-repository writes from a GSD agent worktree that used to pass are now blocked there. Guard hooks now run without blocking other OpenCode 2.x sessions, and a guard that could not run (its script is missing, it crashed, timed out or was killed) is reported as not enforced instead of silently allowing the call. On 2.x, guard advisories now appear in the tool result the model sees, and a git-spec (package) install now registers the GSD commands, agents and skills. The worktree guard now resolves relative paths against the tool's working directory, so a relative write from a GSD agent worktree that resolves into another git repository (such as the main checkout or a nested repository) or into a `.git` directory, including through `../`, is blocked on every runtime that runs the guard.
