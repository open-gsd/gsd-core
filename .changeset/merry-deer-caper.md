**Task commits that name their files no longer sweep in files another session staged** — a bare `git commit` records the whole index. A foreign staged file therefore landed in a commit whose message described only the task. The executor, debugger and debug session manager prompts now name their paths after a `--` pathspec. So do the audit-fix, validate-phase, add-tests and complete-milestone workflows, the git-integration reference and the Pi `gsd-debug` skill. The stop-tracking recipe for `.planning/` now refuses while unrelated paths are staged, and commits only after `git rm` succeeds. The `/gsd-validate-phase` test commit now runs only when the auditor wrote test files. `/gsd-complete-milestone` now commits from the repository top. It stops when it finds more than one staged `.planning` REQUIREMENTS.md deletion, or when the only staged REQUIREMENTS.md deletion lies outside `.planning/`. Its squash merge and merge with history stop unless nothing, or only the one `.planning` REQUIREMENTS.md deletion, is staged. The `/gsd-add-tests` commit now quotes each test path as `':(literal)...'`. The `/gsd-ship` CI-recovery empty commit now records nothing from the index. `/gsd-fast` now stages and commits only the current directory instead of the whole repository. The executor WIP recipe and the worktree-recovery hint of `/gsd-execute-phase` now commit with `-- .` and say they run from the worktree root. The executor prompt now says "never use `git add -f`" in the sentence that bans raw `git add` and `git commit` after a skipped commit. (#5211)
