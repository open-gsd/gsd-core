**Phase-scoped capability hooks now receive the phase they were invoked for, instead of guessing it** — `loop render-hooks <point>` gained an optional `--phase <token>` and returns a typed `context: {phase, phaseDir}`, which every phase-scoped call site across plan, discuss, execute, verify, secure, validate and autonomous now pass. Before this, a hook fired at `plan:pre` while planning Phase 2 had nothing but `STATE.current_phase` (still Phase 1, because Phase 1 is what is executing) or artifact mtimes to infer from, so phase-scoped extensions acted on the wrong phase whenever one phase was planned or verified while another ran. Omitting `--phase` leaves the previous envelope byte-identical, and a token that does not resolve to exactly one phase directory, or is not a safe token, degrades to a warning and a typed `phaseDrop` code rather than failing the render. A `ref.command` handler gets no phase argument when `--phase` drops as `ESCAPES_ROOT`, `DIR_MISMATCH` or `INVALID_TOKEN`, or when `--phase-dir` comes without `--phase` (`PHASE_DIR_ALONE`), where it always got the host's `${PHASE_NUMBER}` before; the other four drops keep the host's `${PHASE_NUMBER}`. A custom phase id outside `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` (a `+`, `@`, `#` or non-ASCII character, or more than 64 characters) drops as `INVALID_TOKEN`, so its `ref.command` handler gets no phase argument either. The same-directory check behind `--phase-dir` (`sameDirectory` in `real-home-guard`, which the test-home sandbox guard also reads) now compares native realpaths on a filesystem that reports inode 0, such as FAT32, exFAT or an SMB share, where it used to answer yes for any two readable directories on the same device. A dropped `--phase` also returns `phaseEchoed`, the values its warning echoes, and an `AMBIGUOUS` drop returns `phaseMore`, the count of candidates beyond the 5 listed, so a caller reads them without parsing the warning text. The verifier-contribution call in `verify-phase-goal.md` now passes `--phase` too. Every phase-scoped `render-hooks` call site, the `verify:post` call in `verify-work.md` included, now also passes `--ws` when the command arguments name a workstream; the `verify:post` call passed no `--ws` before. (#4030)
