# Worktree Recovery Policy

## ORCHESTRATOR FAIL-CLOSED RULE (#48)

> **ORCHESTRATOR FAIL-CLOSED RULE (#48):** `worktree_branch_check` is verify-only — an executor that hits a base/HEAD-namespace mismatch prints `FATAL:` and exits **42** instead of self-recovering. If any executor result reports a `FATAL:`/`exit 42` (or its commits never appear because it halted at the check), mark that plan **blocked**: do NOT merge or clean up its worktree (preserve it for inspection), do NOT count the wave as successful, and surface the mismatch with recovery guidance to the user. The orchestrator — the worktree lifecycle owner — performs any base correction (e.g. recreate the worktree on `{EXPECTED_BASE}`); the sub-agent never does. Never proceed past a halted executor on the assumption it succeeded.

## CHECKPOINT CONTINUATION IN HARNESS-WORKTREE MODE (#6118)

A paused `harness-worktree` executor committed its finished tasks on its own unmerged agent branch A (recorded by `worktree.record-agent` as `{agent_id, worktree_path, branch, expected_base}`); they reach the orchestrator branch only when step 5.5 merges the wave. A fresh `isolation="worktree"` agent forks from the orchestrator HEAD, which does not contain them, so a plain fresh continuation cannot see its own plan's commits. This overrides step 6's "NOT resume" for these plans only.

1. **Paused worktree still exists** (`test -d <worktree_path>`): resume the paused executor by its recorded `agent_id` (`SendMessage`) with the same continuation placeholders. It continues on branch A, which step 5.5 merges as usual.
2. **Otherwise (the harness removed the clean worktree, A is intact):** proceed only while `git rev-parse HEAD` equals A's recorded `expected_base`; when the orchestrator HEAD has moved, the continuation cannot fast-forward, so mark the plan **blocked** under the fail-closed rule above. Dispatch a fresh `isolation="worktree"` continuation with the usual `worktree_branch_check` and add `<paused_branch>{A}</paused_branch>` to its prompt. The executor captures its `GSD_WORKTREE_EXPECTED_BASE` first, then fast-forwards onto A (halting, never resetting or cherry-picking, when it cannot). Record the continuation's entry B with `--base` set to A's `expected_base`, and drop A's entry from the manifest (no verb removes one; rewrite the JSON file: `node -e "const fs=require('fs');const f=process.argv[1];const m=JSON.parse(fs.readFileSync(f,'utf8'));m.worktrees=m.worktrees.filter(e=>e.branch!==process.argv[2]);fs.writeFileSync(f,JSON.stringify(m,null,2))" "$WAVE_WORKTREE_MANIFEST" "<A>"`): B contains A, so the manifest-scoped cleanup merges B alone (merging A as well makes the second merge fail `base_mismatch`). After `worktree.cleanup-wave` succeeds, run `git worktree prune` (the harness removed A's directory, so git still registers it and refuses to delete the branch), then delete every superseded paused branch with `git branch -d`, which git accepts because B's merge made each an ancestor of HEAD. A chain of pauses leaves one superseded branch per pause.

The paused plan's commits still reach the orchestrator branch only through the manifest-scoped cleanup after the plan completes. An `orchestrator-worktree` or sequential plan keeps its existing continuation.

## ISOLATED-RUN RECOVERY — FAIL SAFE (#1292)

> **ISOLATED-RUN RECOVERY — FAIL SAFE (#1292):** When an isolated (worktree) run is *rejected* — the user declines to merge it, the orchestrator surfaces recovery guidance for a blocked/halted plan, or the run over-reached the requested scope — the worktree-isolation contract MUST hold through recovery. Do **NOT** propose continuing on `main`/the primary checkout as the default or recommended recovery path. Default to a **safe halt** and offer: (a) re-attempt in a **fresh, narrowly-scoped worktree**, or (b) inspect or discard the rejected worktree without merging. Any path that edits the primary checkout requires an **explicit, clearly-labeled confirmation** from the user first — editing `main` directly is never the proposed or default option for a run the user configured to be isolated.
